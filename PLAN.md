> Документ для Claude Code. Это техническое задание и план реализации.

## 1. Цель

Персональный Telegram-бот фрилансера-веб-разработчика (сайты + Яндекс Директ для компаний СПб и ЛО), который:

1. **Сам ищет компании** нужной ниши через Yandex Search API по набору поисковых запросов.
2. **Отсеивает мусор**: агрегаторы, гигантов, уже известные домены, не СПб/ЛО.
3. **Аудирует сайты**: технический слой (скрипт) + слой качества (DeepSeek по тексту страницы).
4. **Считает оценку 0–100** «насколько компании нужен новый сайт» и присылает в Telegram только лидов выше порога, в виде карточки с кнопками.
5. **Ведёт CRM**: статусы, заметки, контакты, напоминания «перезвонить».
6. **Строит отчёты** за день / неделю / месяц в заданном формате (раздел 9), по журналу событий.
7. **Черновики писем через DeepSeek** по найденным проблемам сайта.

**Принцип управления: всё строго через команды, reply-меню и inline-кнопки.** Свободного текстового диалога с ботом нет. Текст от пользователя принимается только внутри FSM-сценариев (дата, контакт, заметка, значение настройки) и в `/add`. Любое сообщение вне сценария → бот показывает главное меню.

**DeepSeek используется только для двух задач:** анализ качества сайта (7.4) и черновик письма (10). Никаких других ИИ-функций.

Пользователь один (владелец). Бот отвечает только ID из `ADMIN_IDS`.

Первая ниша — **газификация** (СПб и ЛО). Система должна поддерживать несколько ниш (потом: металлообработка, судостроение, строительство).

## 2. Стек

- Python 3.12
- **aiogram 3.x**: бот, FSM, inline-клавиатуры
- **SQLAlchemy 2.x (async) + aiosqlite**: база SQLite (структура должна позволять переехать на Postgres без переписывания)
- **Alembic**: миграции
- **httpx (async)**: запросы к сайтам и API
- **selectolax** или BeautifulSoup4 + lxml: парсинг HTML
- **Playwright (Chromium)**: этап 4 (скриншоты, мобильная проверка, метрики загрузки)
- **APScheduler (AsyncIOScheduler)**: поиск ночью, напоминания, отчёты
- **openai** (официальный SDK) для DeepSeek: API DeepSeek совместим с OpenAI, через `base_url`
- **pydantic-settings**: конфиг из `.env`
- **loguru**: логи
- **pytest + pytest-asyncio**: тесты
- Запуск: `docker compose` (бот + том для БД) **и** вариант через systemd без Docker

## 5. Модель данных

### 5.1 Таблицы

**niches**: `id, slug, name, is_active, created_at`

**search_queries**: `id, niche_id, text, is_active, last_run_at, results_count`

**companies** (лиды):
- `id, niche_id, domain (unique), url, name, inn, segment (b2b|b2c|unknown)`
- `phones (json), emails (json), messengers (json), address, region_detected`
- `source (yandex|manual|fns|import), source_query, serp_position`
- `status` (enum, раздел 5.2), `score, score_tech, score_quality`
- `next_action_at` (для «перезвонить» и звонка №2), `contact_person, contact_phone`
- `notes (text)`, `tags (json)`
- `created_at, updated_at, last_audit_at, notified_at`

**audits**: `id, company_id, created_at, http_status, final_url, https, ssl_days_left, load_ms, html_kb, scripts_count, images_count, images_no_alt, title, title_len, description, h1 (json), robots_meta, viewport, has_metrika, has_gtag, cms, jquery_version, copyright_year, oldest_upload_year, tel_links, mail_links, messengers (json), forms_count, form_fields (json), anchor_only_ctas, mobile_overflow, issues (json: [{code, severity, title, detail}]), llm_summary (json), screenshot_desktop, screenshot_mobile, raw_text_excerpt`

**events** (журнал, основа отчётов): `id, company_id, from_status, to_status, type, payload (json), created_at`
- `type`: `status_change | note | call_logged | message_sent | reminder_fired | ai_draft`

**reminders**: `id, company_id, due_at, text, is_done, created_at`

**settings**: `key, value`

**llm_usage**: `id, created_at, purpose, prompt_tokens, completion_tokens, cost_rub`

**blacklist_domains**: `domain, reason`. Дополняется из бота кнопкой «В чёрный список».

### 5.2 Статусы

| Код | Подпись | Этап |
|---|---|---|
| `NEW` | 🆕 Новый | отбор |
| `CANCELLED` | ❌ Отменён (сайт норм / не наш) | отбор |
| `SENT` | ✉️ Отправлено | рассылка |
| `REPLIED` | 💬 Ответил | рассылка |
| `IGNORED` | 🙈 Игнор | рассылка |
| `CALL1_NEEDED` | 📞 Нужно созвониться | звонок №1 |
| `CALLBACK` | ⏰ Созвониться потом (дата, время, контакт) | любой |
| `TEST_AGREED` | 🧪 Согласен на тест | звонок №1 → №2 |
| `CALL2_SCHEDULED` | 📅 Звонок №2 назначен (дата, время) | звонок №2 |
| `THINKING` | 🤔 Думает | итог |
| `AGREED` | 🤝 Согласились | итог |
| `REFUSED` | 🚫 Отказ | итог |

«Тест» — промежуточный этап между звонками (например, бесплатный мини-аудит или пробный макет). Подпись этапа вынести в настройки (`TEST_STAGE_LABEL`), по умолчанию «тест».

Переходы не блокировать жёстко: из любого статуса можно в любой через меню «Сменить статус». Но на карточке показывать **рекомендованные кнопки** по текущему статусу:

- `NEW` → ✉️ Отправил · 📞 Созвониться · ❌ Отменить · ⛔ В чёрный список
- `SENT` → 💬 Ответил · 🙈 Игнор · ⏰ Позже
- `REPLIED` / `CALL1_NEEDED` → 📞 Звонок №1 проведён (дальше выбор: 🧪 Тест / 🤔 Думает / 🚫 Отказ / 🙈 Не дозвонился) · ⏰ Позже
- `TEST_AGREED` → 📅 Назначить звонок №2
- `CALL2_SCHEDULED` → ✔️ Звонок №2 проведён (🤝 Согласились / 🤔 Думает / 🚫 Отказ) · ⏸ Перенос
- `THINKING` → ⏰ Напомнить · 🤝 Согласились · 🚫 Отказ

### 5.3 Правило
**Любая смена статуса — только через `crm.service.change_status()`**, которая в одной транзакции обновляет `companies.status` и пишет строку в `events`. Отчёты считаются **только по `events`**, не по текущим статусам.

## 6. Поиск компаний (discovery)

### 6.1 Yandex Search API
- Тарифы (на ноябрь 2026, страница «Правила тарификации Yandex Search API»): 1000 бесплатных синхронных запросов в месяц через **API v1 ночью (00:00–07:59 МСК)**; сверх лимита ночью 360 ₽/1000, днём 480 ₽/1000; API v2 отложенные — 25 ₽/1000.
- Реализуй клиент с двумя режимами (`YANDEX_SEARCH_MODE`):
  - `night_v1`: синхронный API v1, запускается только в ночное окно;
  - `deferred_v2`: отложенные запросы API v2 (создать операцию → опрашивать готовность → забрать результат).
- **Перед реализацией прочитай актуальную документацию Yandex Search API** (эндпоинты, авторизация `Api-Key`, формат ответа XML/JSON, роли сервисного аккаунта, квоты). Не выдумывай формат: если что-то неясно, сделай минимальный пробный запрос и залогируй ответ.
- Параметры: регион `lr` из настроек, страницы 0..N-1, семейный фильтр не нужен.
- Вести счётчик запросов за месяц (в `settings`/`llm_usage`-подобной таблице `api_usage`) и не превышать бесплатный лимит в режиме `night_v1` без явного разрешения (настройка `ALLOW_PAID_SEARCH=false`).

### 6.3 Фильтры (`discovery/filters.py`)
Порядок отсева домена:
1. Нормализация: `www.` убрать, приводить к регистрируемому домену (eTLD+1), поддомены агрегаторов отсекать.
2. Чёрный список (`config/blacklist.yaml` + таблица): avito, profi, 2gis, yandex, vk, ok, youtube, dzen, wikipedia, otzovik, zoon, flamp, spr, orgpage, rusprofile, checko, list-org, hh, superjob, tiu, pulscen, satom, blizko, gosuslugi, госорганы (`*.gov.ru`, `*.gov.spb.ru`), СМИ, форумы, маркетплейсы, крупные газовые сети (`gazprom*`, «Газпром газораспределение», «Петербурггаз», «ПетербургГаз» и т.п.).
3. Уже есть в `companies` (в любом статусе): пропустить.
4. После загрузки главной: не прошёл проверку региона (нет маркеров региона ни в тексте, ни в телефонах) → статус `CANCELLED`, причина `region`, карточку не слать.
5. Нет ключевых слов ниши в тексте → `CANCELLED`, причина `off_niche`.

Отсеянные хранить (чтобы не проверять повторно), но не показывать.

## 7. Аудит

### 7.1 Загрузка (`fetcher.py`)
- httpx, следовать редиректам, таймаут, свой User-Agent, `verify=True`. При SSL-ошибке повторить с `verify=False` и записать проблему `ssl_invalid`.
- Сохранять: финальный URL, статус, время до последнего байта, размер HTML.
- Уважать robots.txt для пути `/` (если запрещено — пометить и проверять только главную страницу один раз).
- Не более `AUDIT_CONCURRENCY` параллельно, не более 1 запроса в секунду на домен.

### 7.2 Технические проверки (`tech_checks.py`)
Каждая проверка возвращает `Issue(code, severity: 1..3, title, detail)`. Список:

| code | Условие | severity |
|---|---|---|
| `site_down` | статус ≥ 400 или таймаут | 3 |
| `no_https` | финальный URL http:// | 3 |
| `ssl_invalid` / `ssl_expiring` | ошибка сертификата / < 14 дней | 3 / 2 |
| `noindex` | meta robots содержит noindex | 3 |
| `no_viewport` | нет meta viewport | 3 |
| `slow_load` | загрузка > 4 с (Playwright) / TTFB > 1.5 с (httpx) | 2 |
| `heavy_page` | HTML > 300 КБ или скриптов > 40 | 1 |
| `no_metrika` | нет mc.yandex.ru / ym( | 2 |
| `title_bad` | нет title, длина < 20 или > 90 | 1 |
| `no_description` | нет meta description | 1 |
| `h1_missing_or_multi` | 0 или > 1 H1 | 1 |
| `images_no_alt` | > 50% картинок без alt | 1 |
| `old_copyright` | год в © < текущий − 2 | 2 |
| `old_uploads` | самый новый год в `/uploads/YYYY/` < текущий − 4 | 2 |
| `old_jquery` | jQuery < 3.0 | 1 |
| `no_tel_link` | нет `tel:` | 2 |
| `no_messengers` | нет wa.me / t.me / viber | 1 |
| `no_form` | нет формы с полем телефона/email | 2 |
| `anchor_ctas` | ≥ 3 кнопок-CTA ведут на `#…` без видимой формы | 1 |
| `mobile_overflow` | scrollWidth > 375 при viewport 375 (Playwright) | 3 |
| `flash_or_frames` | `<object>`/`<embed>` swf, `<frameset>` | 3 |
| `table_layout` | вложенные таблицы для вёрстки | 2 |

Также определить CMS (WordPress, 1C-Bitrix, Tilda, Joomla, MODX, Wix, Nethouse, самопис) по маркерам.

### 7.3 Извлечение (`extract.py`)
- Телефоны (RU-форматы, нормализация в +7XXXXXXXXXX), email, мессенджеры, адрес (по «Санкт-Петербург» / «ул.» / «пр.»), ИНН (10/12 цифр рядом со словом «ИНН», валидировать контрольную сумму), ОГРН, название компании (og:site_name → title → «ООО «…»» в тексте).
- Сегмент: b2c, если в тексте «частный дом», «дача», «коттедж»; b2b, если «промышленн», «объект», «тендер», «застройщик»; иначе unknown.
- **Персональные данные не собирать**: сохранять только общие телефоны и email компании со страницы, ФИО сотрудников не парсить.
- `raw_text_excerpt`: видимый текст, очищенный, до 8000 символов (для ИИ).

### 7.3.1 Реквизиты из Чекко (`integrations/checko.py`)
- ИНН ищется на главной и внутренних страницах (приоритет: «Реквизиты» → «Контакты» → «Услуги» → «О компании», до 3 страниц); форматы «ИНН …», «ИНН/КПП …/…», «И.Н.Н.», проверка контрольной суммы.
- После аудита, если ИНН найден и лид не уходит в отсев, бот запрашивает Чекко (API v2, ключ `CHEKKO_API_KEY`): ООО/АО — `/company` + `/finances` (2 запроса), ИП — `/entrepreneur` (1 запрос).
- В `companies.checko` хранится сводка (не сырой ответ): название, статус, возраст, руководитель (ФИО, ИНН, дата из ЕГРЮЛ), учредители, ОКВЭД, сотрудники, МСП, налоговый режим, выручка и прибыль за последний год с динамикой к прошлому, ссылка на отчёт в ГИР БО, риски (банкротство, недоимка, массовость, РНП, санкции, недостоверный адрес).
- Лимит: `CHECKO_DAILY_LIMIT` (90 из бесплатных 100/сутки), учёт в `api_usage` (`api=checko`); обновление не чаще `CHECKO_REFRESH_DAYS`. Ошибки и лимит не ломают аудит.
- Карточка: блок «🏛 юрлицо · статус · 👔 директор · 📊 выручка · ⚠️ риски · 👋 обращение»; кнопка «🏛 Реквизиты» — подробный экран, «🔄 Обновить», «✏️ Другой ИНН» (ручной ввод, если на сайте ИНН нет или он с ошибкой).
- ФИО руководителя берётся из открытого ЕГРЮЛ через Чекко, а не парсится с сайта.

### 7.4 Слой качества через DeepSeek (`quality_llm.py`)
Вызывать **только** для сайтов, прошедших фильтры и с `score_tech ≥ 20` либо по кнопке «🧠 Глубокий анализ» (экономия бюджета).

Вход: URL, title, description, H1, список найденных тех. проблем, текст страницы (обрезанный), ниша.
Выход: **строго JSON** (response_format json, валидировать pydantic-схемой, при ошибке — 1 ретрай):
```json
{
  "quality_score": 0-100,
  "summary": "1-2 предложения, что с сайтом",
  "problems": [{"title": "...", "why_it_costs_money": "...", "severity": 1-3}],
  "typos": ["..."],
  "price_inconsistencies": ["..."],
  "trust_gaps": ["нет отзывов", "нет лицензий/СРО", "..."],
  "segment": "b2b|b2c|mixed",
  "pitch_angle": "главный крючок для письма одной фразой",
  "is_good_site": true/false
}
```
Если `is_good_site=true` и тех. оценка низкая, автоматически ставить `CANCELLED` с причиной `good_site`.

Промпт (в `prompts.py`): роль — опытный веб-разработчик и маркетолог, оценивает сайт с точки зрения заявок от клиентов; писать по-русски, конкретно, без воды, не выдумывать то, чего нет в тексте.

Примечание: DeepSeek работает с текстом (картинки не отправлять). Скриншоты — только для PDF-аудита и для пользователя.

### 7.5 Оценка (`scoring.py`)
- `score_tech` = сумма весов проблем (severity 3 → 15, 2 → 8, 1 → 3), максимум 100.
- `score_quality` из LLM (если не вызывался — null).
- `score = round(0.5*score_tech + 0.5*score_quality)`, а без LLM `score = score_tech`.
- Бонусы: +5 если найден ИНН, +5 если сегмент совпадает с приоритетным для ниши (настройка), +10 если `site_down`/`no_https`/`noindex`/`mobile_overflow` (горячий лид).
- Веса вынести в настройки, чтобы потом подкрутить. Логировать вклад каждого фактора (показывать в карточке по кнопке «Почему такая оценка?»).

### 8.5 FSM-сценарии
- **⏰ Созвониться потом**: быстрые варианты [Сегодня 15:00] [Завтра 10:00] [Через 3 дня] [Через неделю] [Указать вручную] → (ввод даты/времени в свободной форме, парсить «пт 14:30», «20.11 11:00», «завтра в 12») → контакт (имя/телефон, можно пропустить) → комментарий (можно пропустить) → создать reminder, статус `CALLBACK`, событие.

- **📞 Звонок №1 проведён**: выбор исхода → (опционально) заметка по звонку → событие `call_logged` + смена статуса.

- **⚙️ Настройки**: выбор параметра → ввод значения → валидация.

### 8.6 Напоминания
Каждую минуту проверять `reminders` с `due_at <= now and not is_done`: прислать карточку с пометкой «⏰ Напоминание: …» и кнопками [✅ Сделано] [⏰ Отложить на 1 ч / завтра]. За 15 минут до звонка №2 — предварительное уведомление.

### 8.7 План обзвона на неделю (вместо ежедневной рассылки)
Поиск идёт раз в неделю (`DISCOVERY_CRON`, пн 02:00), ручной `/run` — в любое время.
- **Понедельник, `NEW_LEADS_PUSH_TIME`**: лучшие по оценке лиды из запаса (не больше `LEADS_WEEKLY_LIMIT`) берутся в план недели (`notified_at`). Сводка: новых в плане, в запасе (остаются в `/new` до следующего плана), не обработано с прошлых недель, всего к обзвону и темп «≈N в день до пятницы». Без потока карточек — кнопка «📞 Открыть «Сегодня»».
- **«📞 Сегодня» (`/today`)**: просроченные напоминания, напоминания на сегодня и очередь обзвона — лиды плана и добавленные через `/add` в статусах `NEW` и `CALL1_NEEDED`. Пока статус не сменили, лид остаётся в очереди и переносится на следующий день и неделю (помечается ↪️). Сверху темп: сколько звонков в день нужно, чтобы закрыть очередь к пятнице. Листание по 15.
- **Вт–пт утром**: короткое напоминание «📞 К обзвону: N (≈K сегодня) · напоминаний: M», если есть что делать (`DAILY_QUEUE_REMINDER`).
- **Ручной `/run`**: найденное добавляется в план текущей недели в пределах остатка `LEADS_WEEKLY_LIMIT`, остальное — в запас.

## 9. Отчёты

Считать по `events` за период `[start, end)` в TZ владельца. Формат (точно такой, с эмодзи):

```
📊 Отчёт за 13.11.2026

📍Общий
- Найдено новых лидов — {companies created, status NEW, score ≥ порога}
- Отправлено рассылок — {to_status = SENT}
- Получено ответов в чате — {to_status = REPLIED}
- Попросили созвон позже — {to_status = CALLBACK}

📍Звонок №1 (знакомство)
- Звонков совершено — {call_logged с stage=1}
- Согласны на тест — {to_status = TEST_AGREED}
- Отказ / Игнор — {call_logged stage=1 с исходом REFUSED или IGNORED/no_answer}

📍Звонок №2 (после теста)
- Назначено звонков — {to_status = CALL2_SCHEDULED}
- Звонков совершено — {call_logged с stage=2}
- Отказ / Игнор / Перенос — {stage=2 с исходом REFUSED / IGNORED / RESCHEDULED}

📍Результат дня
- Готовы сотрудничать — {to_status = AGREED}
- Думают / Перезвон — {to_status in (THINKING, CALLBACK)}
- Отказ / Игнор — {to_status in (REFUSED, IGNORED)}

📈 Конверсия: рассылка → ответ {x}% · ответ → звонок {y}% · звонок → сделка {z}%
```
- Ежедневно в `DAILY_REPORT_TIME`, еженедельно (воскресенье, вечер) и ежемесячно (последний день месяца) — автоматически. Недельный/месячный — тот же формат + сравнение с прошлым периодом (▲/▼).
- Под отчётом кнопки: [📅 Другой день] [📆 Неделя] [🗓 Месяц].
- Нулевые строки показывать (как в примере), не скрывать.

  - Рекомендуемая схема: российский VPS (Search API и аудит сайтов работают напрямую) + `TELEGRAM_PROXY` через зарубежный сервер. Альтернатива: зарубежный VPS + `YANDEX_PROXY`/`AUDIT_PROXY` через российский.
  - Свой прокси через SSH-туннель без доп. ПО: `ssh -N -D 127.0.0.1:1080 user@второй_сервер` → `socks5://127.0.0.1:1080`. Подготовить systemd-юнит на `autossh` (автоподъём после обрыва и перезагрузки) и инструкцию в README: SSH-ключ, юнит, проверка.
  - Вариант без второго сервера: купленный индивидуальный SOCKS5-прокси нужной страны. Бесплатные публичные прокси не использовать — через Telegram-прокси проходит токен бота.
  - Команда `/netcheck`: для каждого сервиса (Telegram, Yandex Search API, DeepSeek, аудит) показать, доступен ли он, через какой прокси и с какого внешнего IP идут запросы.
  - Перед деплоем проверить с целевого сервера: `curl -s -o /dev/null -w "%{http_code}" https://searchapi.api.cloud.yandex.net` (`000` = заблокировано → нужен `YANDEX_PROXY`).

## 13. Нефункциональные требования
- Никаких секретов в коде и логах (маскировать ключи).
